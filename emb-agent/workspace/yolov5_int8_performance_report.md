## 7. 性能分析

### 7.1 推理速度提升

- **平均推理时间**: 从 **112.54ms** 降至 **87.34ms**，**降低 22.4%**
- **FPS**: 从 **8.88** 提升至 **11.45**，**提升 28.9%**
- 推理速度提升主要得益于 INT8 量化模型体积更小（减少 46.6%），内存带宽需求降低，以及 INT8 运算在 ARM NEON 上的高效实现

### 7.2 模型体积缩减

- 模型权重从 **3.2MB** 压缩至 **1.7MB**，**减少 46.9%**
- 更小的模型体积意味着更快的加载速度和更低的内存占用
- 对嵌入式设备而言，存储空间的节省非常宝贵

### 7.3 CPU 利用率

- INT8 推理的 user 时间（0.256s）比 FP16（0.308s）减少了 16.9%
- 说明 INT8 量化有效降低了 CPU 计算负担
- sys 时间略有增加（0.063s → 0.074s），可能与模型加载的 I/O 开销有关

### 7.4 检测精度权衡

- INT8 模型在检测精度上有一定损失：
  - 最高置信度目标（狗）从 92.96% 降至 84.60%
  - 低置信度目标（马 77.10%，未知 73.41%）未被检出
- 这是 INT8 量化在精度和速度之间的典型 trade-off

## 8. 优化总结

| 优化维度 | FP16 (优化前) | INT8 (优化后) | 提升幅度 |

## 9. 结论

通过 INT8 量化优化，YOLOv5-Lite (ncnn) 在飞腾派上的推理性能得到了显著提升：

1. **推理速度提升 22.4%**，从 112.54ms 降至 87.34ms，FPS 从 8.88 提升至 11.45
2. **模型体积减小 46.6%**，从 3.22MB 降至 1.72MB，节省了宝贵的存储空间
3. **CPU 计算负担降低 16.9%**，user 时间显著减少
4. **检测精度略有下降**，高置信度目标仍可准确检出，低置信度目标可能被过滤

对于嵌入式场景，INT8 量化是一个非常有价值的优化手段，在可接受的精度损失下获得了显著的性能提升。如果应用场景对精度要求较高，可以考虑使用 FP16 模型；如果对实时性要求更高，INT8 模型是更好的选择。
